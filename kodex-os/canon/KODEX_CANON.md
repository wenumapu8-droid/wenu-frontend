# KODEX−∞ CANON

Status: `CANONICAL / BOOTSTRAP`

## Identity

**Public name:** KODEX−∞  
**Technical name:** `kodex-minus-infinity`  
**Category:** Living Information Design  
**Form:** generative archive, interactive information system and contemplative interface.

## Canonical proposition

KODEX−∞ transforms evidence, memory, cultural research, symbols and human experience into living visual systems. It does not ask the user to passively consume a fixed narrative. It creates a path whose form changes through decisions, preserves the memory of those decisions and converges toward a meaningful return.

## Canonical statements

> Information is not displayed. It is embodied.

> The archive does not store. It remembers.

> The heart does not score. It orients.

> Return is not repetition. Return is transformation carrying memory.

> Every path preserves memory. Every convergence changes the observer.

## Primary product promise

A user should leave each session with:

1. a clearer understanding of a real relationship, pattern, source or unresolved question;
2. a unique visual or narrative artifact produced by the path;
3. visible provenance and uncertainty;
4. a safe and legible return to ordinary orientation;
5. a reason to contribute, share, inspect code or re-enter through another route.

## World structure

### `−∞`

Black, fragmentation, unknown relations, compressed attention, incomplete memory. It is not evil; it is unintegrated potential.

### `THRESHOLD`

Consent, orientation, accessibility settings, intention and first decision.

### `PROLOGUE`

The question and context are established. The user learns how information behaves in this world.

### `DESCENT`

The field narrows. Noise falls away. The user encounters uncertainty, contradiction, absence or hidden structure.

### `ARCHIVE`

Sources, entities, relations and memories become inspectable. Provenance is always available.

### `MACHINE`

The computational system becomes visible: transformations, simulations, generative rules and protocols.

### `HEART`

A central orienting rhythm. Guided pulse and breathing may coordinate attention, but no biometric or spiritual score is invented.

### `COSMOLOGY`

The local path expands into a field of relationships across time, territory, culture, systems and possible futures.

### `RETURN / +∞`

The interface becomes white and spectral color becomes pure. The user receives synthesis, artifact, sources, contribution paths, open-source access and a new entrance.

## Convergence law

All routes may differ in sequence, content, geometry, interaction and intensity, but each canonical route must converge through the following functions:

```text
MEMORY → PROVENANCE → RELATION → REFLECTION → CONTRIBUTION → RE-ENTRY
```

A route that merely links back to a home screen has not achieved convergence.

## Product layers

1. **Evidence layer** — sources, records, measurements, dates and documented relations.
2. **Interpretation layer** — KODEX analysis, editorial framing and pattern recognition.
3. **Speculation layer** — possible futures, simulations and declared hypotheses.
4. **Mythopoetic layer** — symbolic language, ritual, archetype and cosmological expression.
5. **Atmosphere layer** — non-semantic aesthetic material, explicitly declared and never mistaken for data.

The user must be able to distinguish these layers.

## Core engines

- `GLYPH ENGINE` — entities and categories become symbols.
- `RELATION ENGINE` — links, hierarchies, dependencies and contradictions.
- `TIME ENGINE` — accumulation, cycles, sequence, erosion and memory.
- `FIELD ENGINE` — density, flow, interference, force and anomaly.
- `NARRATIVE ENGINE` — questions, reveals, annotations and convergence.
- `MOTION ENGINE` — meaningful state change through movement.
- `EVIDENCE ENGINE` — source acquisition, claims, validation and uncertainty.
- `HEART ENGINE` — orientation, pulse, breath and safe return.
- `CONTRIBUTION ENGINE` — annotation, response, source suggestion and community input.
- `OPEN SOURCE ENGINE` — code inspection, download, examples and reuse boundaries.

## Visual character

KODEX is:

- precise but visionary;
- minimal but not empty;
- strange but legible;
- ritual without claiming religious authority;
- technological without pretending to be scientific instrumentation;
- culturally resonant without generic appropriation;
- dark at entry, luminous at convergence;
- typographically disciplined;
- capable of silence, density and transformation.

KODEX is not:

- a permanent HUD;
- generic cyberpunk decoration;
- a dashboard with mystical labels;
- a wellness score;
- a collection of unrelated loops;
- an archive of copied sacred symbols;
- a linear marketing website.

## Color law

- `−∞`: obsidian, near-black, degraded signal and restrained accents.
- Path states: colors are data-, state- or chapter-dependent.
- `HEART`: warm living red is permitted only as orientation, life or pulse—not danger by default.
- `RETURN / +∞`: white field, full spectral purity and increased spatial openness.

Color never carries essential meaning alone.

## Open-source law

KODEX should expose code, shaders, systems and examples when rights permit. Public repositories must not contain:

- private conversations;
- personal identifiers;
- licensed fonts or assets without redistribution rights;
- restricted cultural knowledge;
- unpublished commercial strategy;
- unreviewed biometric or contemplative data.

## Release law

No deployment occurs without the exact phrase:

```text
APROBAR DEPLOY
```

Until then, work remains in branches, pull requests and previews.
