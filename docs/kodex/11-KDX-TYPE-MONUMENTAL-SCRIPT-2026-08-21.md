# KDX.TYPE / MONUMENTAL SCRIPT × KDX.LIFE
Canon v0.1 · 2026-08-21 · rama nueva del sistema KODEX

> KDX.TYPE / MONUMENTAL SCRIPT is **behavioral, not merely font-based.**

---

## 1 · RAZÓN CANÓNICA

Una familia tipográfica **y conductual** inspirada conceptualmente en la
caligrafía monumental renacentista — *Calligraphiae Monumenta*, Georg Bocskay,
la ornamentación de Joris Hoefnagel. **Inspirada conceptualmente: no se copia
ninguna obra histórica, ni su trazo, ni su composición.**

Lo que se extrae es gramática, no imagen:

| se extrae | no se extrae |
|---|---|
| esqueleto caligráfico | el trazo literal de una página |
| lógica de contraste de trazo | la miniatura, la iluminación |
| comportamiento de ligadura | ornamento floral desconectado de la letra |
| gramática ornamental | alfabetos escolares |
| ocupación del espacio | caligrafía de bodas moderna |
| umbral de legibilidad | |

Su objetivo: títulos, invocaciones, prólogos y statements que operen a la vez
como **lenguaje, imagen y símbolo**.

### Los ocho principios

1. La palabra puede comportarse como organismo.
2. **La legibilidad nunca desaparece por completo.**
3. El ornamento nace del texto, no se le pega encima.
4. Desktop y mobile preservan **relaciones**, no coordenadas.
5. El título puede desplegarse, mutar o colapsar.
6. Este modo **no reemplaza** el resto del sistema tipográfico KODEX.
7. Los flourishes y ligaduras son parte estructural del mensaje.
8. Puede conectarse con comportamiento generativo y autómatas celulares.

## 2 · DÓNDE SÍ Y DÓNDE NO

**Sí:** títulos de escena · prólogos · citas rituales · statements editoriales ·
overlays especiales · nombres de capítulo · placas de transición · portadas ·
momentos narrativos singulares.

**No:** cuerpo de texto largo · micro-UI · etiquetas técnicas · navegación
principal · metadata de lectura rápida · botones chicos · sistemas de datos densos.

> Regla práctica: si el visitante tiene que **leerlo para operar**, no es
> Monumental Script. Si tiene que **sentirlo para entrar**, sí.

## 3 · ESCRITORIO vs TELÉFONO

No es el mismo título más chico. Es el mismo título con otra respiración.

| | escritorio | teléfono |
|---|---|---|
| extensión lateral | amplia | comprimida |
| líneas | libre | **2 a 4, máximo** |
| flourishes | largos, pueden orbitar | contenidos, pegados al contorno |
| campo | compartido con la obra | la obra manda, el título acompaña |
| ornamento | permisivo | jerarquía y lectura primero |
| interacción | puntero disponible | **nunca depende de hover** |

**Lo que se conserva entre los dos: la relación entre esqueleto, ornamento y
vacío. Lo que cambia: cuánto espacio ocupa esa relación.**

## 4 · MOVIMIENTO REDUCIDO

El sistema **no desaparece**. Se conserva la composición y se reducen los
despliegues cinéticos: queda una **versión estática refinada** con microestado
opcional.

Y la regla que ya rige el resto del movimiento en KODEX
(`28-REFERENCE-MOTION-ENGINE`, REDUCED MOTION): bajar la **frecuencia
espacial**, no sólo congelar el tiempo. Un ornamento fino y quieto sigue
siendo incómodo.

    A · SKELETON              la estructura de la letra
    B · LIGATURE              cómo una letra conecta con otra

    D · WORD AS IMAGE         palabras que ya funcionan como emblema

autómata celular (crecimiento, mutación, erosión, colapso).

## 6 · TRES DIRECCIONES DE PROTOTIPO

### 1 · THE ARCHIVE IS WATCHING → *Archive Bloom*
Nace como frase caligráfica limpia. Después crecen filamentos y ornamentos como
si el archivo estuviera recordando — colonizando la tipografía.

    legible y sobrio → las ligaduras se extienden →
    microestructuras florecen desde remates y curvas → vibración sutil en reposo

Célula: **crecimiento periférico / colonización suave.** Los flourishes activan
nodos; no invaden la legibilidad principal.
Escenas: ARCHIVE, PROLOGUE.

### 2 · DESCENT INTO SIGNAL → *Corrupted Descent*
Entra limpio y sufre inestabilidad: trazos que se bifurcan, células que
erosionan y replican segmentos.

    frase clara → partes del trazo se duplican o bifurcan →
    regiones celulares infectan el título → descenso o glitch orgánico

Célula: **mutación / erosión / bifurcación**, por bordes o zonas de alta
curvatura. El texto se descompone y se regenera a la vez.
Escenas: DESCENT, MACHINE como contraste, transiciones rituales.

### 3 · RETURN TO THE SEED → *Collapse to Seed*
Aparece desplegada y viva; después las colonias se repliegan hacia un núcleo.

    presencia plena → nodos celulares laten →
    las extensiones se recogen → núcleo legible + semilla condensada

Célula: **colapso / compresión / retorno.** No es destrucción: es retorno
transformado.
Escenas: RETURN, THRESHOLD en sentido inverso, portadas y finales.

## 7 · KDX.LIFE COMO SUBCAPA TIPOGRÁFICA

**No como fondo decorativo.** Los autómatas son extensiones de la lógica de la
letra:

    Contour Growth        las células crecen por el contorno del título
    Ligature Bloom        las conexiones entre letras brotan como organismos
    Ornamental Infection  letras limpias, y después zonas puntuales mutan
    Archive Moss          colonias pequeñas viven en curvas y remates
    Collapse to Seed      todo vuelve a un nodo o glifo central
    Signal Nesting        micropatrones dentro de trazos anchos

### Parámetros híbridos

```
typeLifeMode: {
  family: "monumental-script",
  behavior: "archive-bloom",
  cellMode: "contour-growth",
  cellDensity: 0.34,
  cellMutation: 0.18,
  flourishLength: 0.72,
  legibilityFloor: 0.76,     // ← piso duro, ver abajo
  memory: 0.53,
  observerInfluence: 0.21,
  reducedMotion: "static-refined"
}
```

### `legibilityFloor` NO ES DECORATIVO
Es el contrato entre el ornamento y la palabra. Ninguna combinación de densidad,
mutación y flourish puede empujar la legibilidad por debajo de ese piso. Cuando
el autómata lo alcanza, **retrocede**: no se detiene el sistema, se retira la
colonia. El principio 2 lo manda — «la legibilidad nunca desaparece por completo».

### Contrato de integración
La tipografía **no dibuja células** y el motor de vida **no dibuja letras**.
El título expone su geometría — contornos, remates, zonas de alta curvatura —
y el autómata la coloniza desde afuera. Dos motores, una superficie.
Así ninguno de los dos tiene que saber cómo funciona el otro.

## 8 · DÓNDE PROBARLO PRIMERO

**Recomendación del creador: ARCHIVE.** Ahí encajan memoria, manuscrito,
archivo, lenguaje como reliquia, crecimiento orgánico. Segunda: PROLOGUE.

**Recomendación de ejecución: PROLOGUE, y por una razón concreta.** Su título
ES literalmente «THE ARCHIVE IS WATCHING» — la frase del prototipo 1 — así que
la prueba se hace sobre texto real y no sobre una maqueta. Además PROLOGUE está
dentro del primer tramo exigido (THRESHOLD → PROLOGUE → DESCENT) y ya tiene
cero solapamientos, así que la prueba aísla la tipografía sin ruido de
composición.

ARCHIVE queda como segunda, apenas la primera se vea bien.

## 10 · ADVERTENCIA DE SISTEMA

**Ya hay dos motores de título en el proyecto:** `TituloCinetico` (operadores
por escena: SCAN, VORTEX, STRATA, ASSEMBLY, ORBIT, RECALL) y `TituloGlitch`
(tres capas sobre el eje −∞·0·+∞, cadencia atada al estado de escena).

MONUMENTAL SCRIPT **no puede ser el tercero.** El requisito 9 del creador es
explícito: «keep this as one family inside KDX.TYPE, not the whole typographic
system». Antes de escribir una línea de este modo hay que decidir cuál de los
dos motores lo aloja. Este proyecto ya tuvo dos KODEX paralelos separados por
218 commits y costó caro.
