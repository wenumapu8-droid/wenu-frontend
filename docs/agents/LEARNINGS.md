## 2026-08-11 — Context architecture

### Learning: the project needs layered memory, not one giant prompt

Durable constitution, current state, priorities and learnings change at different speeds. Keeping them separate reduces stale-context drift and repeated setup work.

**Use:** `KIMI_MASTER_CONTEXT.md` changes slowly; the other three files can change often.

### Learning: generated files are not completion

Across KODEX work, an implementation can exist while remaining unverified, visually weak, branch-isolated or deployment-blocked.

**Use:** completion requires implementation + appropriate evidence + QA + documentation/state update.

## 2026-08-09/11 — Approved plate fidelity

### Learning: plate-to-live is preferable to prose-to-redraw when approved artwork exists

The Heart Chamber lane demonstrates a useful production pattern: preserve the approved plate as the visual source of truth and add restrained live behavior above/around it.

**Use:** before generating a replacement image, search for an approved plate or original Ocín artwork.

### Learning: simulated telemetry must be labelled

If BPM, coherence, signal values or similar metrics are generated by the interface and not measured from a real sensor/data source, label them as simulation.

**Use:** never imply biometric/scientific measurement from decorative telemetry.

## 2026-08-08 — Browser evidence

### Learning: naive screenshot workflows can fabricate layout bugs

Known visual QA traps include incorrect viewport behavior from OS/window clamping, screenshot calls interacting badly with unconditional animation loops, WebGL behavior under disabled GPU paths, shared browser profiles hanging and measurements occurring before webfonts settle.

**Use:** prefer the repository’s proven capture/audit tooling when available. Verify actual viewport dimensions and wait for font readiness.

### Learning: reduced-motion and hidden-tab behavior are part of correctness

A visually rich KODEX scene is incomplete if its motion cannot be reduced or expensive loops continue unnecessarily in hidden/out-of-view states.

## 2026-08-08 — Node graph / build behavior

### Learning: empty generated routes can be a loader/build problem, not missing content

A previous node-route failure was caused by runtime filesystem resolution that did not survive Astro bundling. Compile-time loading restored authored nodes/edges.

**Use:** when a content route is empty, verify build-time data resolution before concluding the archive is missing.

### Learning: sensitivity is not identical to publication block

Scientific precision, attribution sensitivity and source-permission sensitivity can all be “critical” for different reasons. Only some conditions require hard publication blocking.

**Use:** represent cultural/source permission explicitly instead of mapping one broad sensitivity flag to a universal block.

## 2026-08-08 — State / memory

### Learning: multiple incompatible JourneyState APIs have existed across branches

Do not assume a bridge written on one branch is compatible with another just because names look similar.

**Use:** identify the authoritative lineage before adding new producers/consumers or serialized state.

### Learning: pointer behavior should not silently become canonical memory

Ephemeral pointer/touch input may influence visual state, but persistent narrative memory should be produced by explicit, meaningful actions with a declared contract.

## 2026-08-11 — Demoscene / CRT / procedural effects research

### Learning: research must search the repo before creating a new renderer

A Kimi research packet proposed a new lightweight CRT shader, but `redesign-v2` already contains `src/kodex/crt/kodex-crt.esm.js` with scanlines, phosphor masks, noise, flicker, bloom, persistence, chromatic offset, curvature, vignette, bleed, anomaly modes, scene presets and adaptive quality profiles.

**Evidence:** `src/kodex/crt/kodex-crt.esm.js`; `docs/research/KODEX_DEMOSCENE_CRT_RESEARCH_2026-08-11.md`.

**Use:** external CRT research is a benchmark/tuning input. Do not build a parallel CRT implementation unless a measured capability gap justifies it.

### Learning: “external dependency prohibited” is too broad

KODEX prefers internal, lightweight, free/open or already-available capabilities when they solve the need cleanly. That is not the same as a blanket ban on every external dependency.

**Use:** evaluate dependencies by duplication, license, weight, maintainability and actual capability gap. If a robust internal subsystem already exists, extend it instead of adding another package.

### Learning: demoscene timing must not own narrative progression

Small-demo timelines are useful for sequencing shaders, but KODEX is a voluntary/non-linear journey rather than a fixed movie.

**Use:** elapsed time may animate a selected effect; JourneyState + explicit user action + routing own canonical progression.

### Learning: procedural generation is useful when it replaces weight or communicates state

Sine fields and plasma-like shaders can be extremely small and reusable, but “procedural” alone does not make an effect valuable.

**Use:** only add a recipe when it has a declared scene/node function, controllable parameters, reduced-motion behavior and mobile QA.

### Learning: current ASCII subtree contains no `.ans` assets

The audited `src/kodex/ascii/` tree on `redesign-v2` contains renderer/config/scene code but no `.ans` files.

**Use:** do not create an ANSI-import migration task until real assets are present. External ANSI art defaults to `REF` until creator/provenance/rights are verified.

## KODEX durable design learnings

### Visual density needs hierarchy

KODEX can be dense, technical and poster-like, but one primary proposition should dominate. Telemetry and microcopy are support layers.

### Not every scene should be a centered mandala

Rotate composition modes intentionally: orbital, dendritic, topographic, reticular, sequential, cartographic, volumetric, typographic and field-based.

### Motion is a semantic channel

Use motion to express state, relation, energy, scan, reveal, resonance, mutation or memory. Decorative movement without semantic consequence should be reduced.

### Cultural authority outranks aesthetic ambition

Do not generate generic “tribal” motifs, invent permissions or publish sensitive Indigenous/community-held material because it fits the mood.

### Science and spiritual/speculative language can coexist only if labelled honestly

KODEX may connect scientific, visionary, mythic and personal frameworks, but should not present metaphor as scientific proof.

## WËNU MAPU durable learnings

### Commerce truth comes before poetry

Material, fit, size, stock, care and customer-safety information must remain exact even when the brand copy is ritual/poetic.

### Scarcity must be real

One-of-a-kind or low-stock urgency is acceptable when supported by inventory reality. Do not manufacture pressure.

### KODEX and WËNU MAPU share DNA, not identical UX

The store must remain legible and conversion-capable. Experimental KODEX interface behavior should not be copied into commerce merely for visual consistency.

### Product photography is part of the information architecture

For body jewelry, macro detail, material surface, scale and consistent presentation are not optional decoration; they are product information.
