# SEO Audit — Wenu Mapu frontend

Date: 2026-05-15 · Scope: read-only audit of `wenu-frontend` (Astro 6 SSG)
Live: redesign-v2.wenu-frontend.pages.dev · Site canonical: https://wenumapuonline.com

---

## (a) What is already correct

- **Sitemap**: `@astrojs/sitemap` configured with curated per-section priorities and `changefreq`, `lastmod`. Generates `sitemap-index.xml` + `sitemap-0.xml`. `/admin/` excluded.
- **robots.txt**: present, allows all, explicitly allows GPTBot/ClaudeBot/anthropic-ai, blocks SemrushBot/AhrefsBot, references the sitemap. Good.
- **Base.astro meta**: title, description, canonical (absolute, derived from path), full Open Graph (title/description/image/url/type/locale/site_name), Twitter `summary_large_image`, theme-color, `robots index,follow`, favicon, `<link rel=sitemap>`. Solid baseline.
- **JSON-LD coverage**: Home (`Organization` + `WebSite`), product page (`Product` + `BreadcrumbList`), journal post (`Article` + `BreadcrumbList`), category/material/collection pages (`CollectionPage` + `BreadcrumbList`), FAQ (`FAQPage`), care-guide (`HowTo`).
- **Product JSON-LD**: includes `name`, `sku`, `description`, `image[]` (full gallery), `brand`, and an `Offer` with `priceCurrency`, `price` (2-decimal), `availability` mapped from `stock_status`, `url`. Strong.
- **Per-product meta**: unique title (`{name} — Wenu Mapu`, truncated to 60), unique description from cleaned product description truncated to 160 with price fallback. Good.
- **Headings**: single `<h1>` per page checked (home, shop, product, journal, category, material, collection). Hierarchy clean.
- **Lazy loading**: product gallery thumbnails use `loading="lazy"`. Hero is preloaded with AVIF/WebP `<picture>` + `fetchpriority=high`.
- **50 product pages** built in `dist/p/`.

---

## (b) Gaps — prioritized

### CRITICAL
1. **No per-product Open Graph image dimensions / dedicated OG renders.** Product OG falls back to the raw WooCommerce image (`mainImg.src`), which is fine, but pages with **no photo** (`Photography in progress`) inherit `ogImage` = `undefined` → Base falls back to the site hero. Acceptable, but unbranded. No `og:image:width/height/alt` anywhere → poor card rendering on Facebook/LinkedIn/iMessage.
2. **`Product` JSON-LD missing `aggregateRating` / `review` and `priceValidUntil`.** Google Merchant / rich-result eligibility for the Product snippet is weakened without `priceValidUntil` (recommended) and either rating or `hasMerchantReturnPolicy` + `shippingDetails`.

### HIGH
3. **Shop, category, material, collection pages have no `<meta og:image:*>` and reuse a single generic image** (`amulets.webp` reused for 14k-gold, mystic-series, etc.) — misleading and weak for social shares. Each section should have a distinct OG image.
4. **No `ItemList` JSON-LD on shop / category pages.** Listing pages with `CollectionPage` only — adding `ItemList` of products improves crawl signal for the catalogue.
5. **Product images lack descriptive `alt` fallback.** `alt={mainImg.alt || product.name}` — if WooCommerce alt is empty, alt becomes the bare product name (acceptable) but gallery thumbs all repeat the same name. No alt describing the shot. Material/gauge context absent.
6. **No `<meta name="keywords">` is fine, but no `author` / `publisher` on Article JSON-LD verified** — confirm `Article` has `author` + `publisher` with logo.

### MEDIUM
7. **Twitter card missing `twitter:site` / `twitter:creator` handle.**
8. **Sitemap `priority` for `/p/` is 0.8 globally** — fine, but `lastmod` is build-time `new Date()` for every URL, so every page always looks "just modified". Use real product `date_modified` from WooCommerce for product URLs.
9. **No `hreflang`** — site is English-only so currently OK; note for future i18n (mapudungun is phrases only).
10. **No breadcrumb on shop/category pages visually** (JSON-LD exists on category pages — verify it does on shop; shop has `jsonLd` count 0).
11. **`<html lang="en">` is static** — fine for now.

### LOW
12. `humans.txt` present (nice-to-have, neutral).
13. No `og:image` preload; not needed.
14. Consider `manifest.webmanifest` for PWA/icons consistency.

## (c) What's missing for OPTIMAL per-product SEO (owner explicitly asked)

Current product page is good but to be best-in-class each product needs:

1. **`priceValidUntil`** in the `Offer` (e.g. end of year) — required-ish for Product rich results.
2. **`hasMerchantReturnPolicy`** + **`shippingDetails`** in the `Offer` — the site already documents free local delivery + returns; encode it so Google shows the return/shipping badges.
3. **`itemCondition: https://schema.org/NewCondition`** in the Offer.
4. **`weight` / `material` / `size` as schema properties** — product has `attributes` (gauge, material). Map material → `material` and gauge → `size` / `additionalProperty` on the `Product`.
5. **`mpn`** if available, alongside `sku`.
6. **Dedicated branded OG image fallback for photo-less products** — instead of the site hero, a Wenu-branded "piece coming soon" card with the product name. Add `og:image:width`, `og:image:height`, `og:image:alt` (= product name).
7. **Unique, descriptive image `alt` per gallery shot** — e.g. `"{name}, {material}, front view"`. Currently all repeat the product name.
8. **Visible breadcrumb already exists** (good) — keep JSON-LD in sync; current trailing-slash mismatch: visible nav links `/shop` (no slash), JSON-LD uses `/shop/` and `/p/{slug}/`. Astro builds without trailing slash by default → **JSON-LD `item` URLs may 404-canonical-mismatch**. Verify `trailingSlash` config and make JSON-LD URLs match the actual built canonical (the product page itself uses `/p/${slug}` without slash in `productLd.offers.url` but `/p/${slug}/` with slash in breadcrumb — inconsistent).
9. **Product `description` for meta** strips HTML well, but ensure it's not empty for the ~photo-less SKUs; fallback exists.
10. **Related products** rendered (`RelatedPieces`) — good for internal linking; ensure those links are crawlable `<a href>` (verify).
11. **No `<link rel="prev/next">`** — N/A for single product, but relevant if product galleries paginate.
12. **Consider `Review`/`aggregateRating`** once reviews exist — biggest rich-result win.

## (d) Concrete actions, file by file

**`src/pages/p/[slug].astro`**
- Fix breadcrumb URL inconsistency: make `breadcrumbLd` items and `productLd.offers.url` both match the real canonical (pick with-or-without trailing slash to match `astro.config.mjs` `trailingSlash`, default = ignore → use no trailing slash consistently).
- Extend `productLd.offers`: add `priceValidUntil`, `itemCondition: 'https://schema.org/NewCondition'`, `hasMerchantReturnPolicy`, `shippingDetails`.
- Add `material` and `additionalProperty` (gauge/size) to `productLd`.
- Pass branded fallback `ogImage` when `mainImg` is undefined.
- Generate descriptive `alt` per image using name + material + index.

**`src/layouts/Base.astro`**
- Add `<meta property="og:image:width">`, `og:image:height`, `og:image:alt` (accept new optional props `ogImageAlt`, `ogImageWidth/Height`).
- Add `<meta name="twitter:site">` / `twitter:creator` with the brand handle.

**`astro.config.mjs`**
- In `serialize`, set `lastmod` from real product/page modified dates for `/p/` URLs instead of global `new Date()`.

**`src/pages/shop.astro`**
- Add `CollectionPage` + `ItemList` JSON-LD (currently `jsonLd` count = 0).
- Give it a distinct OG image (already uses `meteorite-banner.webp` — acceptable, keep).

**`src/pages/material/*`, `src/pages/collection/*`, category pages (`amulets`, `ear-cuffs`, etc.)**
- Replace shared `amulets.webp` OG image with section-specific images.
- Add `ItemList` JSON-LD listing the products shown.

**`public/` (assets)**
- Create `public/img/og/` with one OG image (1200×630) per major section + a branded product fallback.
- Optionally add `manifest.webmanifest`.

**`src/pages/journal/[slug].astro`**
- Verify `Article` JSON-LD includes `author`, `publisher` (with logo `ImageObject`), `datePublished`, `dateModified`.

---

## Summary

Foundations are strong: sitemap, robots, canonical, OG/Twitter baseline, and JSON-LD on every page type including a near-complete `Product` schema. The remaining work is depth, not breadth: enrich the `Product` offer (return/shipping/condition/priceValidUntil), fix a trailing-slash inconsistency in breadcrumb/offer URLs, add section-specific and branded-fallback OG images with explicit dimensions, add `ItemList` to listing pages, and use real `lastmod` dates. None are blockers for launch; all are needed for "professional, complete" SEO especially at product level.
