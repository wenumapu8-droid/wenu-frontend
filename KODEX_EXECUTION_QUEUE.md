# KODEX−∞ EXECUTION QUEUE

Status: ACTIVE production queue. Purpose: keep KODEX advancing without waiting for ad-hoc prompts. This queue does not create new architecture; it orders bounded work against the current product lineage and `KODEX_EXPERIENCE_GATE.md`.

## Operating law

Every work unit must end in one of two outcomes:

1. a browser-visible, evidence-backed improvement tied to one exact SHA; or
2. a precise hard blocker with the smallest safe next action.

No work unit may count as progress if its only output is planning, agent coordination, terminal logs, or a build PASS with no visible product delta.

## Write ownership

One integrator/write owner at a time for scene runtime files.

Secondary agents may only:
- inspect references;
- recover assets/provenance;
- audit mobile/desktop;
- run browser QA;
- propose bounded patches;
- prepare the NEXT scene package.

Do not let multiple agents independently redesign the same scene.

## Queue states

- NOW = active highest-leverage work
- NEXT = immediately follows NOW
- READY = sufficiently specified and can start without creator input
- LATER = valid but lower leverage
- BLOCKED = requires a concrete missing dependency
