## Cycle algorithm

### A — OBSERVE

Determine:

- exact branch and SHA;
- dirty files and whether they belong to an unfinished prior KDX.RAE cycle;
- highest-priority executable item in `KODEX_EXECUTION_QUEUE.md`;
- relevant current implementation;
- governed reference / mockup / frame / previous evidence;
- existing tests and mechanisms that could satisfy the task.

If there are coherent unfinished RAE changes, continue and validate them before starting another frontier.

### B — COMPARE

Compare CURRENT against DESIRED using the Experience Gate and exact task contract.

Produce a small divergence set. Do not solve ten things at once.

### C — CHOOSE

Choose the smallest high-leverage divergence that can materially improve KODEX this cycle.

Prefer:

1. closing an incomplete visible causal interaction;
2. restoring reference/North-Star fidelity;
3. fixing mobile choreography;
4. making motion/data/state truthful;
5. connecting two already-existing systems;
6. only then adding a genuinely missing mechanism.

### D — DELEGATE

Use at most the specialists actually needed. Ask them for evidence, not generic opinions.

### E — ACT

Implement one coherent bounded delta. Reuse existing primitives, engines, tokens, registries and assets.

Never solve a visual problem by embedding the mockup as the runtime world.
Never fabricate live data.
Never add glitch, particles, holography, terminal copy or HUD merely as surface decoration.
Every effect should communicate state, depth, relation, memory, causality or atmosphere.

### F — VERIFY

Run the narrowest meaningful validation first, then broader gates as justified.

For scene changes, verification should converge toward:

- exact source diff;
- relevant unit/contract tests;
- `npm run test:kodex:core` when appropriate;
- `npm run audit:kodex:integrity` when appropriate;
- build when warranted;
- real-browser evidence when the delta is visual/interactive;
- desktop 1440 and mobile 390×844 / 412×915 when closing a scene gate;
- reduced-motion behavior where relevant;
- console/runtime cleanliness;
- data-truth classification;
- same-region/same-function comparison against governed visual reference.

A green build is not a visual PASS.

### G — RECORD

Return a structured cycle result. The external KDX.RAE runner persists the machine log; avoid creating scratch documentation unless it is an explicitly required source-of-truth update.

### H — STOP

One cycle = one coherent delta or blocker. Stop after validation. The next scheduled cycle will re-observe from disk rather than trusting your memory.
