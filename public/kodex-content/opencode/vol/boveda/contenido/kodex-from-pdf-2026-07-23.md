# KODEX−∞ — base narrativa y build spec derivada del PDF

## Qué confirma el PDF

El PDF NO es solo un portfolio de imágenes.
Trae una cosmología verbal bastante clara y repetitiva, con tres capas fuertes:

1. **manifiesto / statement**
2. **serie de portales / capítulos**
3. **lectura de detalle / loop / sombra / yayentru**

La tesis central que aparece una y otra vez:

- el diseño deja de ser humano y se vuelve sistema
- la geometría no es decoración; es organismo / código / pulso
- el blanco y negro funciona como binario sagrado
- cada obra es portal, nodo, activación o protocolo
- la experiencia ideal no es “ver trabajos” sino entrar en un sistema vivo

## Crítica curatorial honesta

## Lo más fuerte

### 1. Tiene lenguaje propio
No depende solo de “geometría bonita”.
Tiene un vocabulario insistente:
- portal
- pulso
- código
- frecuencia
- organismo
- memoria
- activación
- caos / orden

Eso permite construir sistema, no solo branding.

### 2. La obra aguanta una lectura de archivo
Varias piezas se sienten como entradas de códice o protocolo.
Sirven para una web que organiza, revela y activa, en vez de solo mostrar thumbnails.

### 3. El blanco y negro tiene tesis
No se lee como elección estética vacía.
El PDF le da razón conceptual: binario sagrado, sombra/luz, señal antes del algoritmo.
Eso le da mucha fuerza si el sitio mantiene severidad.

## Lo más débil

### 1. El texto a veces sobre-explica la mística
En varios tramos cae en acumulación de términos grandes:
- ancestral
- cósmico
- protocolo espiritual-digital
- otra dimensión
- conciencia humana

No siempre rompe, pero si se copia textual completo al sitio puede sonar demasiado declamatorio.
La web debería **editar y comprimir**.

### 2. El Behance exportado mete ruido
Hay muchas páginas con UI, botones, metadata y cortes torpes.
Eso confirma que el micrositio no debe "embeber Behance" sino **destilarlo**.

### 3. Falta jerarquía sistémica cerrada
El PDF ya tiene materiales de capítulo, pero no una arquitectura 100% consistente de estratos.
La web puede resolver eso mejor que el PDF.

## Traducción propuesta: del PDF al micrositio

## Tesis
La web no debe reemplazar la obra con UI ni con geometría inventada.
La web debe:
- aislar la obra
- darle jerarquía
- activar movimiento/pulso
- conectar capítulos
- traducir algunas capas a ediciones, colaboración o commission

## Build spec resumido para Claude/Codex

### Goal
Build a premium microsite `/kodex` inside the Wenu frontend, using real source artworks and fragments from the KODEX PDF as the primary visual material.

### Non-negotiables
- do not invent replacement geometry
- interface organizes and activates the real work
- black / white / gray only
- portal feeling, not portfolio
- smooth descent, not normal navigation
- CTAs feel like threshold triggers, not ecommerce buttons

### Version 1 stack
- Astro or lightweight HTML/CSS/JS inside existing frontend
- GSAP for motion
- Lenis optional for smooth scroll
- SVG masks / image crops / blend modes for real artwork fragments
- no heavy WebGL required in v1

### Required routes
- `/kodex`
- `/kodex/archive/[slug]`
- `/kodex/editions`

### Suggested first content map
- `/kodex` → p.4 + p.12+p.5 copy
- `/kodex/archive/conjuncion` → p.29
- `/kodex/archive/respiracion` → p.28
- `/kodex/archive/sol-negro` → p.62
- `/kodex/editions` → p.62 + Yayentru framing

### Components
- `KodexHeader`
- `SignalToggle`
- `ThresholdCTA`
- `ArchiveIndex`
- `ChapterHeroArtwork`
- `LoopPreviewPane`
- `SystemReading`
- `FragmentCitation`
- `NextLayerCard`
- `EditionArchiveEntry`
- `CollaborateBlock`

### Motion language
- breath
- pulse
- reveal
- descent
- resonance
- proximity response

### Avoid
- grid-heavy portfolio layout
- startup cleanliness
- fake sci-fi dashboard
- product-card energy
- decorative sacred-geometry filler

## Recomendación final

**No construir todavía los 6 estratos completos.**

Primero construir:
1. portal
2. 1 archive page canon (`Conjunción`)
3. editions/collaborate

Si eso respira bien, recién después expandir a más capítulos.
